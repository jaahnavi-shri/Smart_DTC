1. THE PROJECT IN ONE MINUTE
==============================================================================
Smart DTC is a website written in Python with the Flask library. It has two
kinds of users who share ONE database, so a change made by one is seen by
the other within a few seconds, without reloading the page.

The whole site works like an app: a vertical menu on the left goes to every
page, and on a laptop every page fits on the screen without scrolling. A
button at the bottom of the menu switches between the light design (navy
menu, light pages) and a dark navy design.

COMMUTERS (no login)
  - Home: a small "Live buses" window (next stop, a countdown that ticks
    every second, on time or late, free seats), a few totals and the
    "Already booked?" box, with plenty of space around everything
  - LIVE TRACKING, like the train-status screen of a train app: for every
    bus the next stop, the expected arrival time, how many minutes away it
    is, and a clear "Running late by X minutes" message when it is late.
    A vertical timeline shows every stop: the stops already passed, where
    the bus is now (a little bus on the line) and the stops still to come,
    each with its timetable time, its expected time and its delay
  - Buses & Booking: search and sort the buses, and book a seat on a seat
    map that shows which seat will be yours; you get a digital ticket with
    a unique code (DTC-5B0FF42E)
  - passengers aged 70 or above, women and differently-abled passengers
    get PRIORITY ACCESS tickets automatically; everyone else gets a
    SMART TICKET
  - About: one tab with two parts, "Why Smart DTC" (our mission, the
    problem, our solution, the UN goals, our team) and "Impact" (what the
    site has done so far, with bar charts)

DEPOT ADMIN (password: dtc2026)
  - the "Login" button at the top right of every page opens a small login
    form; after the right password three admin pages appear in the menu:
  - FLEET OVERVIEW: how many buses are running, and for every bus the
    passengers on board (which the admin can change), where it is now,
    where it is going and when it gets there, on time or late
  - MANAGE ROUTES: add a bus to a route by choosing a pickup and a
    drop-off stop (the stops in between are found for you), its number of
    seats, and whether it runs on a timetable ("Enable scheduling", with
    its first departure time); turn the timetable of any bus on or off
  - DEMAND & SURGE (kept from our report): how many commuters wait at each
    stop. 35 or more waiting (one full busload) = SURGE, 25 to 34 =
    RISING, below 25 = NORMAL. A relief bus can be dispatched to a SURGE
    stop: it is saved with a label such as RELIEF-2CC1 and the waiting
    number goes down by 35 (never below 0)

EXTRA: the Python Lab page shows live examples of all ten experiential labs,
for our teacher.

ABOUT "LIVE": there is no real GPS box in a bus for a student project, so
app.py SIMULATES the buses. Every bus follows a TIMETABLE on its real route
through Noida (30 km/h, 1 minute at each stop, there and back all day), and
traffic can make it late on any stretch of road. Section 7, part 5 explains
how.

5. HOW A WEB PAGE IS MADE, AND HOW IT STAYS LIVE
==============================================================================
Every click follows the same 5 steps:

  BROWSER                      app.py (Flask)                  smartdtc.db
  -------                      --------------                  -----------
  1. You click "Book seat"
     on DTC-425:
     GET /book/1   -------->   2. Flask finds the route
                                  @app.route("/book/<int:bus_id>")
                                  and runs book(bus_id=1)
                               3. get_bus(1) asks the database --> buses
                                                         <-- one row
                               4. render_page("book", ...) fills
                                  index.html with that bus
  5. The booking page  <----      the finished HTML is sent back
     appears.

Two kinds of request:
  GET   "show me a page"             opening a link, the search box
  POST  "here is a form, save it"    booking, login, admin forms

After a POST that saved something, the code answers with redirect(...):
the browser goes to another page (for example /ticket/DTC-5B0FF42E). This
stops a booking being saved twice if someone presses Refresh.

flash("message") keeps a one-time message for the next page that is shown.
index.html shows it as a pop-up (green = success, red = error, blue =
information) that disappears after a few seconds. Messages about logging in
are shown inside the login form instead.

session is a small signed cookie in the browser. Smart DTC keeps two
things there: admin = True after a correct login, and my_tickets, the last
5 ticket codes booked in that browser (listed on the Home page).

HOW THE PAGES STAY LIVE WITHOUT RELOADING
  6. Home, Buses, Book and the Fleet overview: the JavaScript at the bottom
     of index.html asks app.py for /api/live every 5 seconds (fetch()).
     api_live() (line 1386) answers with JSON: every bus (next
     stop, seconds to it, how late, seats, where it is) and every stop.
     The JavaScript writes the new numbers into the page.
  7. Live Tracking: every 5 seconds the JavaScript asks for
     /track/1?part=live. app.py answers with only the moving part of the
     page, already made into HTML by the tracker_live macro, and the
     JavaScript swaps it in. So the timeline is written ONCE, in
     index.html, and Python does all the work.
  Between two answers, the countdowns tick every second inside the browser:
  each one remembers the moment the bus arrives (data-deadline) and shows
  how far away that moment is.

6. THE DATABASE: smartdtc.db
==============================================================================
SQLite keeps the whole database in one file, so bookings stay saved after
the program is closed (this is our file handling). The 4 tables are linked
by id numbers. They are made by init_db() (line 250) using the
SQL in SCHEMA (line 209).

  buses       id, number, route, occupied, total, scheduled,
              first_departure
              route holds the stops in order, separated by "|":
              "Bennett University | Pari Chowk | Knowledge Park II |
               Sector 142 | Botanical Garden"
              occupied = passengers on board, total = seats
              scheduled = 1 if the bus runs on its timetable, 0 if not
              first_departure = when its timetable began; everything
              else about where the bus is comes from the clock
  stops       id, name, waiting
  tickets     id, code, bus_id, name, age, category, priority (1 or 0),
              seat, status, created_at
              bus_id = the id of the bus in the buses table
  dispatches  id, label, stop_id, waiting_before, waiting_after, created_at
              stop_id = the id of the stop in the stops table

Starting data (SAMPLE_BUSES and SAMPLE_STOPS, line 173):
  DTC-425  Bennett University -> Botanical Garden   23/35, next stop in 6 min
  DTC-347  Pari Chowk -> Noida Sector 18            29/35, next stop in 9 min
  DTC-534  Botanical Garden -> ITO, Delhi           34/35, next stop in 4 min
  Waiting: Bennett University 12, Pari Chowk 24, Botanical Garden 34
The stop names and their positions are real places; the timetables and
the traffic are simulated, as our report says for the tracking page.

Safe SQL: values are never pasted into the SQL text. We write ? and pass
the values separately:
    query_one("SELECT * FROM buses WHERE id = ?", (bus_id,))
This "parameterised query" blocks SQL injection (someone typing SQL into a
form). (bus_id,) with a comma is a tuple with one item.

To look inside the database, install the free program "DB Browser for
SQLite" and open smartdtc.db. Close it again before you book tickets.

4. RECURSION (line 494)
------------------------------------------------------------------------------
Every recursive function has a BASE CASE (an answer known without another
call) and a SMALLER STEP (a call on a smaller problem) (E9).

to_binary(n)                                               line 498
    Base case: n < 2 -> str(n).
    Smaller step: to_binary(n // 2) + str(n % 2).
    to_binary(11) = to_binary(5) + "1"
                  = to_binary(2) + "1" + "1"
                  = to_binary(1) + "0" + "1" + "1" = "1011"
ticket_pattern(code)                                       line 507
    Draws the 8 x 8 square pattern on every ticket. For each of the 8
    characters after "DTC-":
      int("5", 16) = 5 -> to_binary(5) = "101" -> zfill(4) = "0101"
      -> add its reverse bits[::-1]: "0101" + "1010" = "01011010"
    "1" is a dark square, "0" a white one. Each code gives its own
    pattern, so a conductor can compare it at a glance.
arrival_times(first_eta, gaps)                             line 520
    Minutes until a bus reaches each stop ahead. gaps holds the minutes
    from each stop to the next one (driving + waiting).
    Base case: no gaps left -> [first_eta].
    Smaller step: [first_eta] + arrival_times(first_eta + gaps[0],
                                              gaps[1:])
    arrival_times(6, [3, 10]) -> [6, 9, 19]
    Every bus timetable is built with it: trip_plan() in part 5.
gcd(a, b)                                                  line 533
    Euclid: gcd(a, 0) = a, otherwise gcd(b, a % b). gcd(28, 35) = 7.
simplify_fraction(top, bottom)                             line 541
    28/35 -> "4/5" by dividing both numbers by their gcd.
factorial(n)                                               line 549
    Base case n <= 1 (this also catches 0). 5! = 120 = the number of
    different orders in which 5 stops could be driven.
to_binary and arrival_times are used by the website; gcd,
simplify_fraction and factorial are shown on the Python Lab page. The
recursion is never deep: to_binary(15) makes 4 calls and a route of 10
stops makes 9, far below Python's limit of about 1000.

5. BUS TIMETABLES AND LIVE STATUS (line 559)
------------------------------------------------------------------------------
THE IDEA. A real system would read GPS from each bus. We have no GPS, so
every bus follows a TIMETABLE, like a train: it leaves its first stop at
its first departure time, drives stop to stop at 30 km/h, waits 1 minute
at each stop, rests 15 minutes at the end of its route, then drives back.
Trip 0 goes forwards, trip 1 comes back, trip 2 goes forwards again, all
day. Traffic can make a bus late on any stretch of road. The database
keeps only ONE time per bus (first_departure): from that time and the
clock, Python works out everything else, so nothing else is saved.

DISTANCES
  stop_point(name)              (latitude, longitude) of a stop; an unknown
                                stop is put in the middle of Noida instead
                                of crashing (.get() with a default)
  distance_km(a, b)             line 594
                                the haversine formula: the distance
                                between two points on a round Earth
                                (radius 6371 km). map(math.radians, ...)
                                turns degrees into radians (E8), ** squares
  segment_points(a, b)          the two stops plus the road points between
                                them from ROUTE_VIA; the other way round
                                the same points are reversed with [::-1]
  path_length_km(), stretch_km(), route_km()
                                add up the straight pieces; zip(points,
                                points[1:]) pairs each point with the next

THE TIMETABLE
  drive_minutes(a, b)           line 641
      km / 30 * 60, rounded UP to a whole minute with math.ceil()
      (Bennett University -> Pari Chowk: 7.4 km = 15 minutes)
  trip_plan(stops)              line 648
      when the bus is due at every stop, in minutes after it leaves the
      first one, e.g. [0, 15, 19, 42, 65]; arrival_times() (recursion)
      adds up the drives and the 1-minute waits
  cycle_minutes(stops)          one trip + the 15-minute layover

TRAFFIC (WHY A BUS IS LATE)
  traffic_minutes(number, trip, stretch)                     line 666
      the minutes a bus loses on one stretch of one trip: 0 (a clear road,
      55 out of 100 times) or 1 to 4. random.Random(seed) makes random
      numbers that are always THE SAME for the same seed (here the bus
      number, trip and stretch), so every page and every refresh agree.
  trip_delays(number, trip, stop_count)                      line 676
      a running total of that traffic: how late the bus is at each stop
      of the trip (never more than 12 minutes; the first stop is always
      on time)
  first_departure_for(number, stops, first_eta, now)         line 689
      for the sample buses: a first departure two round trips ago that
      puts the bus exactly first_eta minutes from its next stop now, so
      after a reset the ETAs are the ones in our report (6, 9 and 4)

WHERE IS THE BUS NOW?
  trip_timetable(number, stops, trip, start)                 line 699
      one trip: the stops in driving order (% 2 tells even from odd
      trips), the time DUE at each stop (start + trip_plan) and the time
      EXPECTED there (due + delay)
  current_trip(number, stops, first_departure, now)          line 718
      the trip number is (now - first_departure) // cycle: // between two
      time spans counts the whole cycles. A bus that has finished its
      trip rests at the end, so we show its next trip.
  where_is(info, now)                                        line 735
      "waiting" at the first stop before it leaves, "moving" between two
      stops (position 1.25 = a quarter of the way from stop 1 to stop 2),
      or "at_stop" for its minute at a stop. A for loop with break finds
      the first stop it has not reached yet.
  timeline_rows(info, mode, coming, now)                     line 759
      one row per stop for the Live Tracking timeline: due time, expected
      time, delay, km from the start, and the state: "passed", "here",
      "next" or "later" (an if-elif ladder)
  live_status(number, stops, scheduled, first_departure, now) line 813
      everything the pages show about a bus right now: running or not,
      next stop, seconds to it, expected and due clock times, how late
      (late and late_text), where it is ("Between Pari Chowk and Knowledge
      Park II"), its destination and arrival there, and the timeline rows.

      (sqlite3.IntegrityError), the Flask import (ImportError),
      find_free_port() (OSError)
    - except ... as error: book() and admin_routes() show str(error)
    - else: book() saves the ticket only if no error was raised;
      admin_routes() saves the bus only then; find_free_port() returns
      the free port
    - finally: every database helper closes the connection, and
      save_ticket() closes it even after return
    - raise: validate_booking() and validate_new_bus() raise ValueError
      with our own messages
    - robust without try: stop_point() uses .get() with a default, and a
      broken first departure starts the bus from midnight (bus_view())
    - three kinds of errors: a SyntaxError stops the program before it
      starts; exceptions (runtime errors) are caught as above; logical
      errors (wrong answers, like the "same seat for everyone" bug in our
      report) are only found by testing

14. QUESTIONS THE TEACHER MAY ASK, WITH SHORT ANSWERS
==============================================================================
 1. Why Flask?
    It is a small Python web library: a route is just a Python function,
    so the program logic stays in Python that every member can explain.
 2. Why SQLite and not a text or CSV file?
    We have 4 tables linked by ids (a ticket belongs to a bus, a dispatch
    to a stop). SQLite keeps them in one file, comes with Python, and
    lets us search, count and update with SQL.
 3. What is a route?
    A web address connected to a function with @app.route("/buses").
    Visiting the address runs the function, which returns the page.
 4. What is a decorator? Explain admin_required.
    A function that wraps another function to add something before or
    after it. admin_required checks session["admin"] first and sends you
    to the login form if it is missing. @wraps keeps the page's name.
 5. How do you stop SQL injection?
    We never put typed text inside SQL. We use ? and pass the values
    separately, so they are always treated as data.
 6. How is the ticket code made, and how do you know it is unique?
    "DTC-" + 8 hex characters from uuid4(). save_ticket() checks the
    database in a while loop and makes a new code if it is already used.
    The database column is also UNIQUE. 16 ** 8 = about 4.3 billion codes.
 7. How do you decide priority?
    is_priority(): age >= 70 or category in ("Woman", "Differently
    Abled"). The result is stored as 1 or 0 in the ticket.
 8. Why 35 for a surge?
    It is the seating capacity of one bus: 35 people waiting fill a
    whole extra bus. 25 to 34 is RISING, an early warning.
 9. What happens if two people book the last seat at the same moment?
    save_ticket() starts with BEGIN IMMEDIATE, which locks the database.
    The second booking waits, then sees the bus is full. We tested 50 at
    once.
10. Is the bus tracking real?
    The stops and distances are real; the movement is simulated, because
    we have no GPS in a bus. Each bus follows a timetable worked out from
    real distances at 30 km/h, and traffic makes it late. With real GPS,
    only live_status() would change: it would read the position instead
    of calculating it.
11. How do you know a bus is late, and by how much?
    The timetable says when it is DUE at each stop (trip_plan()). Traffic
    adds minutes on each stretch (traffic_minutes()), and the running
    total is the delay (trip_delays()). Expected time = due time + delay.
    late_text() turns the delay at the next stop into "Running late by
    3 minutes".
12. Your traffic is random. Why does every page show the same delay?
    random.Random(seed) always gives the same numbers for the same seed.
    Our seed is the bus number, the trip and the stretch, so the delay of
    one stretch is fixed, and every page and refresh agree.
13. How does Manage routes find the stops between pickup and drop-off?
    build_stop_network() makes a dictionary of sets: each stop and its
    neighbours on any route. find_route() does a breadth-first search:
    first all stops 1 step away, then 2 steps, and so on, remembering how
    each was reached. When it reaches the drop-off, it walks back. That
    gives the route with the fewest stops.
14. How does the page change without pressing Refresh?
    JavaScript calls fetch() every 5 seconds. On most pages app.py sends
    JSON from /api/live; on Live Tracking it sends the finished HTML of
    the timeline (/track/1?part=live), which is swapped in. Countdowns
    tick every second in the browser between two answers.
15. How does the login form open?
    It is a <dialog> element in index.html. The Login button calls its
    showModal(). The form inside is sent to /admin like any form; after a
    wrong password, app.py sends you back with ?login=1, which opens it
    again with the message.
16. Where is file handling?
    The database file smartdtc.db (sqlite3), style.css read with open()
    in stylesheet(), and os.remove() in reset_db(). The path is built
    with os.path.join so it works on Windows, Mac and Linux.
17. Show recursion. What are the base case and the smaller step?
    to_binary(n): base case n < 2; smaller step to_binary(n // 2).
    arrival_times(): base case no gaps left; smaller step gaps[1:].
18. continue, break and pass in your code?
    suggest_another_bus(): continue skips full or parked buses, break
    stops at the first free one. mark_boarded() only has pass.
19. Why try / except / else / finally in book() and save_ticket()?
    except catches a bad age or name and shows a message; else saves the
    ticket only when there was no error; finally always closes the
    database connection, even after return.
20. Can you test one function without the website?
    Yes, in the interactive shell (E1). In the project folder type
    python (Mac and Linux: python3), then:
        >>> import app
        >>> app.classify_demand(35)
        'SURGE'
        >>> app.late_text(3)
        'Running late by 3 minutes'
        >>> app.trip_plan(["Bennett University", "Pari Chowk"])
        [0, 15]
        >>> app.to_binary(11)
        '1011'
        >>> exit()
21. Why does the website not scroll?
    style.css makes the frame exactly the window's height (100vh) with a
    grid of menu + page, and turns scrolling off. Each page is laid out to
    fit; @media rules make spacing tighter on shorter screens. On phones
    the page scrolls normally, because a phone screen is too small.
22. What did testing find?
    Two bugs (in our report): a non-number age crashed the app (fixed with
    try/except ValueError), and every booking got the same seat (fixed by
    adding 1 to occupied after each ticket).

15. COMMON PROBLEMS AND HOW TO FIX THEM
==============================================================================
"'python' is not recognized"  (Windows)
    Python is not on PATH. Reinstall and tick "Add python.exe to PATH",
    or type py instead of python (py app.py).

"Flask is not installed. In a terminal, run: pip install flask"
    Run that command in the same terminal (Mac/Linux:
    python3 -m pip install flask), then python app.py again.

"error: externally-managed-environment" when running pip
(Homebrew Python on a Mac, Ubuntu)
    Make a virtual environment once, inside the project folder:
        python3 -m venv .venv
        source .venv/bin/activate      (Windows: .venv\Scripts\activate)
        pip install flask
        python app.py
    Next time, run only the "source" line and then python app.py.
    (If Ubuntu says venv is missing: sudo apt install python3-venv.)

The Login button does nothing
    Refresh the page. A very old browser may not know <dialog>; then use
    an up-to-date Chrome, Edge, Safari or Firefox.

I logged in but cannot find the admin pages
    They are in the menu on the left under "Depot admin": Fleet
    Overview, Manage Routes, Demand & Surge. On a narrow window the menu
    shows only icons: hover over them to see the names.

Live Tracking says "No buses are running right now"
    Every bus has its timetable switched off. Log in, open Manage routes
    and click "Turn on", or run "python app.py reset".

A new bus says "Not started"
    Its first departure time is later today. It starts by itself then.

The page scrolls, or something is cut off
    The layout is made for laptop screens. Make the browser window
    bigger or full screen (Mac: Ctrl + Cmd + F), or zoom out
    (Cmd + minus / Ctrl + minus). A very long route scrolls inside its
    own timeline box.

The buses are somewhere else every time I open the site
    That is the timetable: the buses keep driving even while the site is
    closed. "python app.py reset" starts every bus again.

The countdown says "Now" and the time looks wrong
    The timetables use the computer's clock. Check the date and time on
    the computer.

The page shows {{ ... }} or has no data
    You opened index.html directly. Run app.py and open the address it
    prints.

The page has no colours
    style.css is not in the same folder as app.py.

"Address already in use", or a "403 Forbidden" page on a Mac
    Another program uses the port. app.py moves to 5001 by itself; use
    the address printed in the terminal. On a Mac you can also turn off
    System Settings > General > AirDrop & Handoff > AirPlay Receiver.

My change to app.py does not show
    Stop the server (CTRL + C) and start it again. For changes to
    style.css or index.html a browser refresh is enough.

"database is locked"
    Close DB Browser for SQLite (or click "Write Changes" in it).

I forgot the admin password
    It is ADMIN_PASSWORD in app.py (dtc2026), and the terminal prints it
    when the server starts.

I want the starting data back
    python app.py reset

16. WORDS TO KNOW
==============================================================================
Flask          a Python library for making websites
route          a web address joined to a Python function
template       an HTML file with gaps ({{ }}) that Flask fills in
Jinja2         the template language Flask uses
macro          a reusable piece of a Jinja2 template, like a function
GET / POST     asking for a page / sending a form
redirect       telling the browser to go to another address
flash message  a one-time message shown on the next page
session        small data kept in a signed browser cookie
SQLite         a database stored in a single file
SQL            the language for asking a database questions
table, row     a table is like a sheet; a row is one record in it
commit         save the changes to the database file
rollback       cancel the changes since the last commit
transaction    changes that are saved all together or not at all
JOIN           reading two linked tables together (ticket + its bus)
decorator      a function that wraps another function (@admin_required)
lambda         a small one-expression function without a name
recursion      a function that calls itself on a smaller problem
base case      the case a recursive function answers without calling itself
exception      an error while the program runs (ValueError, KeyError, ...)
timetable      when a bus is due at every stop
layover        the rest at the end of a route before the bus drives back
delay          expected time minus due time: how late the bus is
seed           the starting value of a random number generator: the same
               seed always gives the same "random" numbers
breadth-first  searching step by step outwards: everything 1 step away,
  search       then 2 steps, ... finds the way with the fewest steps
latitude,      a position on Earth: degrees north and degrees east
  longitude
haversine      the formula for the distance between two such positions
simulation     working out what WOULD happen, here from a timetable
JavaScript     the language web browsers run; it keeps our pages live
JSON           text that holds lists and dictionaries, for sending data
API            a way for one program to ask another for data (/api/live)
fetch()        JavaScript asking a web address for data without reloading
<dialog>       an HTML box that opens on top of the page (the login form)
CSS variable   a named value in style.css, like --accent: #2f6bff
media query    a CSS rule only for some screen sizes (@media)
404            "not found": the page or item does not exist
port           the number after the colon in 127.0.0.1:5000
127.0.0.1      "this computer" (the site is only on your own machine)
